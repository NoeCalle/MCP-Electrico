# Release mirror runbook

## Purpose

This runbook turns a validated MCP Eléctrico release into a portable export that can later be copied to an **independent repository**.

The independent repository is intentionally separate from the active development repository. CI artifacts are useful staging packages, but they are not considered the final independent backup.

## Current stable source

```text
release_id = MCP_ELECTRICO_0_9_REFERENCE_VALIDATED
commit_sha = 5228e358cf0716dc963f109a15b9e1a2d309f635
recovery_branch = stable/0.9-reference-validated
manifest = releases/mcp_electrico_0_9_reference_validated.json
```

## Build the export

From a full clone of MCP Eléctrico:

```bash
python scripts/create_release_export.py \
  --ref 5228e358cf0716dc963f109a15b9e1a2d309f635 \
  --expected-sha 5228e358cf0716dc963f109a15b9e1a2d309f635 \
  --release-manifest releases/mcp_electrico_0_9_reference_validated.json \
  --output-dir release_export \
  --name mcp_electrico_0_9_reference_validated
```

The command fails if the requested ref, expected SHA, and release manifest do not agree.

## Export contents

```text
release_export/
├── mcp_electrico_0_9_reference_validated-source.zip
├── mcp_electrico_0_9_reference_validated.bundle
├── release_manifest.json
├── export_metadata.json
└── SHA256SUMS.txt
```

The source ZIP is generated by `git archive` from the approved commit, not from the current working tree. The Git bundle contains repository history reachable from temporary refs pointing only to that approved commit.

Secrets, untracked local files, environment files outside Git, and generated private dossiers are therefore not intentionally included.

## Verify the package

Recompute every row in `SHA256SUMS.txt` before using the package. Also verify the Git bundle:

```bash
git bundle verify mcp_electrico_0_9_reference_validated.bundle
```

## Restore from the bundle

A clean restoration can be created without GitHub:

```bash
mkdir restored-mcp
cd restored-mcp
git init
git fetch ../release_export/mcp_electrico_0_9_reference_validated.bundle \
  refs/heads/__mcp_export_tmp__/5228e358cf07:refs/heads/main
git checkout main
git rev-parse HEAD
```

The final command must print exactly:

```text
5228e358cf0716dc963f109a15b9e1a2d309f635
```

P11D will automate this clean-restore proof.

## Independent mirror repository

When the separate mirror repository is created, restore the bundle into a clean local repository first, verify the SHA, then add the mirror as a remote and push the verified history.

Conceptually:

```bash
git remote add mirror <independent-mirror-repository>
git push mirror main
```

Do not use the mirror as a feature-development remote. It should receive only stable, verified snapshots.

## Security boundary

Never add these manually to the mirror/export package:

- API keys or tokens;
- `.env` files with credentials;
- private project dossiers;
- client drawings or models not already approved for publication;
- local caches, virtual environments or editor state.

The mirror protects product source and release evidence; it is not a backup location for confidential engineering projects.
