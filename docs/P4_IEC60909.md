## Referencia normativa objetivo

La referencia objetivo del desarrollo iniciado en agosto de 2026 es:

- **IEC 60909-0:2026**;
- edición 3.0;
- publicación 2026-07-23;
- fuente oficial de metadata: `https://webstore.iec.ch/en/publication/68454`.

IEC 60909-0:2016 fue sustituida por la edición 2026. El proyecto no presume que un backend desarrollado contra una edición anterior sea automáticamente conforme a 2026.

El texto completo de la norma no se distribuye en el repositorio. La revisión de conformidad de edición se mantiene como criterio independiente del gate P4.

## Backend candidato

`pandapower 3.5.x` es el backend principal candidato porque su módulo `pandapower.shortcircuit` implementa el método de fuente de tensión equivalente declarado como DIN/IEC EN 60909 y expone `calc_sc()`.

Política vigente:

```text
preferred_engine = pandapower
automatic_dispatch = false
crosscheck = false
professional_emission = false
target_edition_conformance = UNVERIFIED_AGAINST_TARGET_EDITION
```

La conformidad específica con IEC 60909-0:2026 no se dará por supuesta y corresponde a P4C10.

## P4B / P4C04 — 3F MAX/MIN

`mcp_electrico.iec60909.ejecutar_3ph()` implementa:

- falla trifásica `3ph`;
- escenario `max` o `min` explícito;
- fuente P2 con Scc3/X-R;
- conversión trazable `R/X = 1 / (X/R)` al `ext_grid` pandapower;
- líneas trifásicas R1/X1;
- transformadores P2 compatibles con el puente pandapower;
- `Ik''` (`ikss_ka`);
- `Sk''` normalizada como `sqrt(3) * Un * Ik''`;
- Rk/Xk equivalente;
- motor, versión, edición objetivo y estado de conformidad;
- `professional_emission=false`.

Para MIN con líneas se exige `endtemp_degree` explícita por línea. No se supone una temperatura final oculta.

## P4C09A — benchmark independiente 3F

El alcance 3F MAX/MIN está contrastado contra una implementación analítica independiente de pandapower/OpenDSS en `mcp_electrico.iec60909_benchmarks`.

El benchmark verifica una red equivalente 22.9 kV + línea radial y compara:

- `Ik''`;
- `Sk''`;
- Rk;
- Xk.

Runner reproducible:

```bash
python examples/benchmark_p4_3ph.py --output benchmark_p4_3ph.json
```

El CI exige `pass=true`. Esto cierra el subhito **P4C09A**, pero P4C09 global continúa `PENDING` mientras no exista cobertura independiente del resto del alcance P4-v1.

## P4C05 — ip e Ith

Los motores 3F y 2F permiten solicitar `ip` e `Ith` mediante:

```text
calcular_ip_ith = true
topology = radial | meshed
tk_s > 0
kappa_method = C
```

Reglas fail-closed:

- `topology="auto"` no se acepta;
- `tk_s` debe ser finito y positivo;
- P4 v1 admite únicamente `kappa_method="C"` para este alcance;
- si falta cualquiera de estos datos, no se ejecuta `ip/Ith`;
- el payload conserva los parámetros efectivos en `input_projection.duty`.

Resultados adicionales cuando se solicitan:

- `ip_ka` → corriente de pico `ip`;
- `ith_ka` → corriente térmica equivalente `Ith`.

`tk_s` no se inventa porque su valor depende del tiempo de despeje que más adelante deberá vincularse con P5/TCC.

## P4C06 — falla bifásica 2F

`mcp_electrico.iec60909_two_phase.ejecutar_2ph()` implementa la falla fase-fase sin tierra (`2ph`) para MAX y MIN.

La cadena reutiliza los datos P2 de fuente y secuencia positiva, pero hace visible la condición del alcance v1:

```text
negative_sequence_policy = P4C06_Z2_EQUALS_Z1_SYMMETRIC_PASSIVE_SCOPE
Z2 = Z1
scope = red simétrica pasiva soportada actualmente
universal_assumption = false
```

La igualdad `Z2 = Z1` no se presenta como regla universal ni se aplica silenciosamente a generadores, motores o modelos asimétricos. El puente pandapower vigente rechaza esos elementos fuera de alcance.

Resultados contractuales 2F actuales:

- `Ik''` (`ikss_ka`);
- Rk;
- Xk;
- `ip` e `Ith` cuando se solicitan con parámetros explícitos.

Aunque pandapower expone `skss_mw`, P4C06 no lo promociona a `Sk''` contractual para 2F. El valor se conserva en `backend_raw` mientras la normalización específica no esté contratada y validada.

Para MIN con líneas sigue siendo obligatoria `endtemp_degree` explícita por línea.

### Benchmark independiente 2F

`mcp_electrico.iec60909_benchmarks_2ph` resuelve el caso esperado por componentes simétricas sin usar pandapower ni OpenDSS como fuente del resultado:

```text
I1 = E / (Z1 + Z2)
Z2 = Z1        [solo alcance P4C06 declarado]
Ik''_2F = sqrt(3) * |I1|
         = c * Un / (2 * |Z1|)
```

Para el mismo equivalente positivo también se comprueba:

```text
Ik''_2F / Ik''_3F = sqrt(3) / 2
```

El benchmark cubre MAX/MIN y compara `Ik''`, Rk y Xk dentro de tolerancias versionadas. Esto permite marcar **P4C06 = DONE**, pero no cierra P4C09 global.

La misma pestaña **Cortocircuito** puede mostrar simultáneamente estudios 3F y 2F vigentes para la misma `model_revision`; un estudio no sobrescribe al otro.

Para cada estudio V4 muestra:

- barra y tipo de falla;
- escenarios MAX y MIN;
- `Ik''`;
- `Sk''` cuando el contrato de la falla lo define actualmente (3F; en 2F se muestra `—`);
- `ip` e `Ith` cuando fueron solicitados;
- Rk y Xk;
- topología, `tk_s` y método κ efectivos;
- motor y versión runtime;
- edición normativa objetivo;
- estado de conformidad de edición;
- madurez `EXPERIMENTAL_P4`;
- `professional_emission=false`;
- issues por escenario cuando un cálculo queda bloqueado.

En 2F V4 muestra además la política de secuencia negativa `Z2 = Z1`, su alcance restringido y `universal_assumption=false`. La ausencia de `Sk''` contractual 2F se presenta como `—`; JavaScript no deriva ningún valor para llenar la tabla.

Si MAX puede calcularse pero MIN falla por falta de `endtemp_degree`, el resultado global queda incompleto y V4 muestra el issue; no copia MAX, no inventa temperatura y no rellena MIN.

Al activar la pestaña, V4 resalta las barras de falla registradas en el mismo unifilar e integra la primera con el inspector existente. JavaScript solo presenta el snapshot: no calcula corrientes, impedancias ni criterios IEC 60909.

P4C11A y P4C11B son subhitos visuales cerrados. **P4C11 global continúa `PENDING`** hasta completar el alcance final de fallas que cierre P4-v1.

## Mapeo P2 → pandapower

```text
scc_max_mva -> s_sc_max_mva
scc_min_mva -> s_sc_min_mva
X/R max     -> rx_max = 1 / (X/R max)
X/R min     -> rx_min = 1 / (X/R min)
```

La inversión queda visible en `input_projection.source` y está protegida por tests.
