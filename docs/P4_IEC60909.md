# P4 — Cortocircuito IEC 60909

## Estado

**EN PROGRESO — P4A foundation.**

P3-v1 está cerrada con limitaciones y P4 es la fase principal activa. P4 no se considera implementada por la sola existencia de `pandapower.shortcircuit.calc_sc()`.

## Referencia normativa objetivo

La referencia objetivo del desarrollo iniciado en agosto de 2026 es:

- **IEC 60909-0:2026**;
- edición 3.0;
- publicación 2026-07-23;
- fuente oficial de metadata: `https://webstore.iec.ch/en/publication/68454`.

IEC 60909-0:2016 fue sustituida por la edición 2026. El proyecto no presume que un backend desarrollado contra una edición anterior sea automáticamente conforme a 2026.

El texto completo de la norma no se distribuye en el repositorio. La revisión de conformidad de edición se mantiene como criterio independiente del gate P4.

## Backend candidato

`pandapower 3.5.x` es el backend principal candidato porque su módulo `pandapower.shortcircuit` implementa el método de fuente de tensión equivalente declarado como DIN/IEC EN 60909 y expone `calc_sc()`.

La política sigue siendo:

```text
preferred_engine = pandapower
automatic_dispatch = false
crosscheck = false
professional_emission = false
```

El backend candidato y la edición normativa objetivo son dos cosas distintas. Hasta completar la revisión correspondiente:

```text
target_edition_conformance = UNVERIFIED_AGAINST_TARGET_EDITION
```

## Alcance de fallas

### 3F

Pandapower expone `fault="3ph"` y `case="max"|"min"`. Es el primer alcance numérico de P4-v1 porque utiliza secuencia positiva y coincide con los datos P2 ya disponibles de Scc3/X-R, líneas R1/X1 y transformadores `%Z`/R-X.

### 2F

Pandapower expone `fault="2ph"`. Se incorporará después de cerrar el primer benchmark 3F y deberá tener validación independiente propia.

### 1F-T

Pandapower expone `fault="1ph"`, pero el proyecto no la habilitará hasta validar la cadena de secuencia cero de:

- red equivalente;
- líneas;
- transformadores;
- neutro/puesta a tierra cuando corresponda.

La existencia de datos Z0 en P2 no implica todavía que su proyección pandapower esté validada.

### 2F-T

La API documentada `calc_sc()` no expone un token directo de falla bifásica a tierra. P4 no la aproximará como `2ph` ni `1ph`. Requiere una estrategia separada o un backend/capa complementaria y permanece fuera del P4-v1 inicial.

## Mapeo de fuente P2 → pandapower

P2 almacena X/R. Pandapower solicita R/X en `ext_grid`:

```text
scc_max_mva -> s_sc_max_mva
scc_min_mva -> s_sc_min_mva
X/R max     -> rx_max = 1 / (X/R max)
X/R min     -> rx_min = 1 / (X/R min)
```

Esta inversión debe quedar visible en resultados/tests. Nunca se pasará X/R directamente a un campo R/X.

## Magnitudes

Resultados que pandapower expone directamente en `res_bus_sc` según el alcance solicitado:

- `ikss_ka` → `Ik''`;
- `skss_mw` → potencia inicial de cortocircuito, pendiente de normalización/justificación de etiqueta de unidad en la capa MCP;
- `ip_ka` → `ip` cuando se solicita;
- `ith_ka` → `Ith` cuando se solicita.

`Ib` (corriente simétrica de corte) e `Ik` (corriente permanente) no tienen un campo directo equivalente en el contrato inicial y **no se derivarán por una fórmula improvisada**. Permanecen pendientes de estrategia P4.

## Primer bloque numérico siguiente — P4B

P4B debe implementar únicamente:

1. adaptación explícita de fuente P2 a `ext_grid`;
2. líneas R1/X1;
3. transformadores P2 con `vk_percent`/`vkr_percent`;
4. falla 3F;
5. escenarios max/min;
6. `Ik''` y potencia inicial por barra;
7. resultado estructurado con motor, versión, edición objetivo y estado de conformidad;
8. tests que demuestren X/R → R/X;
9. `professional_emission=false`.

No se habilitarán aún 1F-T, 2F-T ni emisión profesional.
