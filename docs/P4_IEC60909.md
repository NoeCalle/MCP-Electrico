## Referencia normativa objetivo

La referencia objetivo del desarrollo iniciado en agosto de 2026 es:

- **IEC 60909-0:2026**;
- edición 3.0;
- publicación 2026-07-23;
- fuente oficial de metadata: `https://webstore.iec.ch/en/publication/68454`.

IEC 60909-0:2016 fue sustituida por la edición 2026. El proyecto no presume que un backend desarrollado contra una edición anterior sea automáticamente conforme a 2026.

El texto completo de la norma no se distribuye en el repositorio. La revisión de conformidad de edición se mantiene como criterio independiente del gate P4.

## P4B — 3F max/min

`mcp_electrico.iec60909.ejecutar_3ph()` implementa:

- falla trifásica `3ph`;
- escenario `max` o `min` explícito;
- fuente P2 con Scc3/X-R;
- conversión trazable `R/X = 1 / (X/R)` al `ext_grid` pandapower;
- líneas trifásicas R1/X1;
- transformadores P2 compatibles con el puente pandapower;
- `Ik''` (`ikss_ka`);
- `Sk''` normalizada como `sqrt(3) * Un * Ik''`;
- Rk/Xk equivalente;
- motor, versión, edición objetivo y estado de conformidad;
- `professional_emission=false`.

Para el escenario mínimo con líneas se exige `endtemp_degree` explícita por línea. No se supone una temperatura final oculta.

## P4C05 — ip e Ith

La función 3F y el motor 2F permiten solicitar `ip` e `Ith` mediante:

```text
calcular_ip_ith = true
topology = radial | meshed
tk_s > 0
kappa_method = C
```

Reglas fail-closed:

- `topology="auto"` no se acepta; la topología debe declararse explícitamente;
- `tk_s` debe ser finito y positivo;
- P4 v1 admite únicamente `kappa_method="C"` para este alcance;
- si falta cualquiera de estos datos, no se ejecuta `ip/Ith`;
- el payload conserva los parámetros efectivos en `input_projection.duty`.

Resultados adicionales cuando se solicitan:

- `ip_ka` → corriente de pico `ip`;
- `ith_ka` → corriente térmica equivalente `Ith`.

`tk_s` no se inventa porque su valor depende del tiempo de despeje que más adelante deberá vincularse con P5/TCC para estudios completos.

## P4C06 — falla bifásica 2F

`mcp_electrico.iec60909_two_phase.ejecutar_2ph()` implementa la falla fase-fase sin tierra (`2ph`) para MAX y MIN.

La cadena reutiliza los datos P2 de fuente y secuencia positiva, pero hace visible la condición necesaria para el alcance v1:

```text
negative_sequence_policy = P4C06_Z2_EQUALS_Z1_SYMMETRIC_PASSIVE_SCOPE
Z2 = Z1
scope = red simétrica pasiva soportada actualmente
universal_assumption = false
```

La igualdad `Z2 = Z1` no se presenta como regla universal ni se aplica silenciosamente a generadores, motores o modelos asimétricos. El puente pandapower vigente ya rechaza esos elementos fuera de alcance.

Resultados contractuales 2F actuales:

- `Ik''` (`ikss_ka`);
- Rk;
- Xk;
- `ip` e `Ith` cuando se solicitan con parámetros explícitos.

Aunque pandapower expone `skss_mw`, P4C06 no lo promociona a `Sk''` contractual para 2F. El valor se conserva únicamente en `backend_raw` mientras la normalización específica no esté contratada y validada.

Para MIN con líneas sigue siendo obligatoria `endtemp_degree` explícita por línea.

### Benchmark independiente 2F

`mcp_electrico.iec60909_benchmarks_2ph` resuelve el caso esperado por componentes simétricas sin usar pandapower ni OpenDSS como fuente del resultado.

La referencia aplica:

```text
I1 = E / (Z1 + Z2)
Z2 = Z1        [solo alcance P4C06 declarado]
Ik''_2F = sqrt(3) * |I1|
         = c * Un / (2 * |Z1|)
```

Para el mismo equivalente positivo, el benchmark también comprueba:

```text
Ik''_2F / Ik''_3F = sqrt(3) / 2
```

El benchmark cubre MAX/MIN y compara `Ik''`, Rk y Xk dentro de tolerancias versionadas. Esto permite marcar **P4C06 = DONE**, pero no cierra P4C09 global.

## P4C11A — primera vista Workspace V4

P4C11A incorpora el primer consumo visual de resultados IEC 60909 reales sin introducir un segundo motor de cálculo en el navegador.

La arquitectura es:

```text
iec60909.ejecutar_3ph()
        ↓
iec60909_suite.ejecutar_3ph_max_min()
        ↓
workspace_state.record_study("iec60909_3ph", ...)
        ↓
workspace V3 existente
        ↓
workspace_p4_view (V4)
```

La suite conserva por separado los payloads `max` y `min`. Si MAX puede calcularse pero MIN falla por falta de `endtemp_degree`, el resultado global queda incompleto y V4 muestra el issue; no copia MAX, no inventa temperatura y no rellena MIN.

La tool pública explícita actual es:

```text
ejecutar_cortocircuito_iec60909_3ph
```

No reemplaza el `FaultStudy` histórico de OpenDSS y no participa en despacho automático ni cross-check.

La pestaña **Cortocircuito** muestra, para la revisión vigente:

- barra de falla y tipo 3F;
- escenarios MAX y MIN;
- `Ik''` y `Sk''`;
- `ip` e `Ith` cuando fueron solicitados;
- Rk y Xk;
- topología, `tk_s` y método κ efectivos;
- motor y versión runtime;
- edición normativa objetivo;
- estado de conformidad de edición;
- madurez `EXPERIMENTAL_P4`;
- `professional_emission=false`;
- issues por escenario cuando un cálculo queda bloqueado.

Al activar la pestaña, V4 resalta la barra de falla en el mismo unifilar e integra esa barra con el inspector existente. JavaScript solo presenta el snapshot: no calcula corrientes, impedancias ni criterios IEC 60909.

Caso reproducible:

```bash
python examples/workspace_p4_3ph.py
```

Genera `workspace_p4_3ph.html` y `workspace_p4_3ph_unifilar.svg`. El fixture usa 20 °C explícitos en la línea únicamente para mantener el caso matemático reproducible; no se publica como recomendación de diseño.

P4C11A se considera el **subhito visual 3F**. La representación 2F se incorporará como un subhito V4 posterior reutilizando snapshots; P4C11 global continúa `PENDING`.
