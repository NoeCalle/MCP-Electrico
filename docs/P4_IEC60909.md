# P4 — Cortocircuito IEC 60909

## Estado

**EN PROGRESO — P4B 3F max/min experimental.**

P3-v1 está cerrada con limitaciones y P4 es la fase principal activa. P4 no se considera implementada ni validada por la sola existencia de `pandapower.shortcircuit.calc_sc()`.

## Referencia normativa objetivo

La referencia objetivo del desarrollo iniciado en agosto de 2026 es:

- **IEC 60909-0:2026**;
- edición 3.0;
- publicación 2026-07-23;
- fuente oficial de metadata: `https://webstore.iec.ch/en/publication/68454`.

IEC 60909-0:2016 fue sustituida por la edición 2026. El proyecto no presume que un backend desarrollado contra una edición anterior sea automáticamente conforme a 2026.

El texto completo de la norma no se distribuye en el repositorio. La revisión de conformidad de edición se mantiene como criterio independiente del gate P4.

## Backend candidato

`pandapower 3.5.x` es el backend principal candidato porque su módulo `pandapower.shortcircuit` implementa el método de fuente de tensión equivalente declarado como DIN/IEC EN 60909 y expone `calc_sc()`.

La política sigue siendo:

```text
preferred_engine = pandapower
automatic_dispatch = false
crosscheck = false
professional_emission = false
```

El backend candidato y la edición normativa objetivo son dos cosas distintas. Hasta completar la revisión correspondiente:

```text
target_edition_conformance = UNVERIFIED_AGAINST_TARGET_EDITION
```

## P4B — primer motor numérico

`mcp_electrico.iec60909.ejecutar_3ph()` implementa el primer alcance numérico P4:

- falla trifásica `3ph` únicamente;
- escenario `max` o `min` explícito;
- fuente P2 con Scc3/X-R;
- conversión trazable `R/X = 1 / (X/R)` al `ext_grid` pandapower;
- líneas trifásicas R1/X1 del modelo soportado;
- transformadores P2 compatibles con el puente pandapower;
- `Ik''` (`ikss_ka`);
- `Sk''` normalizada en MCP como `sqrt(3) * Un * Ik''`;
- Rk/Xk equivalente reportado por el backend;
- motor, versión, edición objetivo y estado de conformidad visibles;
- `professional_emission=false`.

Para el escenario mínimo con líneas, P4B exige `endtemp_degree` explícita por línea. No se supone 20, 90, 250 °C ni otra temperatura final. Si falta, devuelve `P4SC201` y no ejecuta el cálculo.

P4B reutiliza inicialmente la compatibilidad del puente pandapower P1.5/P2. Por ello, para transformadores exige también la ficha P2 completa que ese puente necesita. Esta condición es conservadora y puede separarse en un adaptador P4 dedicado más adelante si la evidencia lo justifica.

## Alcance de fallas

### 3F

**IMPLEMENTADA EXPERIMENTALMENTE EN P4B.** Pandapower expone `fault="3ph"` y `case="max"|"min"`. Es el primer alcance numérico porque utiliza secuencia positiva y coincide con los datos P2 ya disponibles de Scc3/X-R, líneas R1/X1 y transformadores `%Z`/R-X.

La implementación no equivale aún a validación normativa: falta P4C09 y P4C10.

### 2F

Pandapower expone `fault="2ph"`. Se incorporará después del primer benchmark independiente 3F y tendrá validación propia.

### 1F-T

Pandapower expone `fault="1ph"`, pero el proyecto no la habilitará hasta validar la cadena de secuencia cero de:

- red equivalente;
- líneas;
- transformadores;
- neutro/puesta a tierra cuando corresponda.

La existencia de datos Z0 en P2 no implica todavía que su proyección pandapower esté validada.

### 2F-T

La API documentada `calc_sc()` no expone un token directo de falla bifásica a tierra. P4 no la aproximará como `2ph` ni `1ph`. Requiere una estrategia separada o un backend/capa complementaria y permanece fuera del P4-v1 inicial.

## Mapeo de fuente P2 → pandapower

P2 almacena X/R. Pandapower solicita R/X en `ext_grid`:

```text
scc_max_mva -> s_sc_max_mva
scc_min_mva -> s_sc_min_mva
X/R max     -> rx_max = 1 / (X/R max)
X/R min     -> rx_min = 1 / (X/R min)
```

Esta inversión queda visible en el payload `input_projection.source` y está protegida por tests. Nunca se pasa X/R directamente a un campo R/X.

## Magnitudes

P4B publica actualmente:

- `ikss_ka` → `Ik''`;
- `skss_mva` → `Sk''` normalizada por MCP;
- `rk_ohm`;
- `xk_ohm`.

También conserva `skss_mw` crudo de pandapower y verifica su coherencia numérica con la magnitud normalizada, sin reutilizar el nombre de unidad del backend como contrato profesional de MCP.

Pendientes:

- `ip_ka` → `ip` en P4C05;
- `ith_ka` → `Ith` en P4C05;
- `Ib` e `Ik`, que no tienen campo directo equivalente en el contrato inicial y **no se derivarán por una fórmula improvisada**.
