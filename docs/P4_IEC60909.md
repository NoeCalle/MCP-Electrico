## Referencia normativa objetivo

La referencia objetivo del desarrollo iniciado en agosto de 2026 es:

- **IEC 60909-0:2026**;
- edición 3.0;
- publicación 2026-07-23;
- fuente oficial de metadata: `https://webstore.iec.ch/en/publication/68454`.

IEC 60909-0:2016 fue sustituida por la edición 2026. El proyecto no presume que un backend desarrollado contra una edición anterior sea automáticamente conforme a 2026.

El texto completo de la norma no se distribuye en el repositorio. La revisión de conformidad de edición se mantiene como criterio independiente del gate P4.

## P4B / P4C04 — 3F MAX/MIN

`mcp_electrico.iec60909.ejecutar_3ph()` implementa:

- falla trifásica `3ph`;
- escenario `max` o `min` explícito;
- fuente P2 con Scc3/X-R;
- conversión trazable `R/X = 1 / (X/R)` al `ext_grid` pandapower;
- líneas trifásicas R1/X1;
- transformadores P2 compatibles con el puente pandapower;
- `Ik''` (`ikss_ka`);
- `Sk''` normalizada como `sqrt(3) * Un * Ik''`;
- Rk/Xk equivalente;
- motor, versión, edición objetivo y estado de conformidad;
- `professional_emission=false`.

Para MIN con líneas se exige `endtemp_degree` explícita por línea. No se supone una temperatura final oculta.

## P4C09A — benchmark independiente 3F

El alcance 3F MAX/MIN está contrastado contra una implementación analítica independiente de pandapower/OpenDSS en `mcp_electrico.iec60909_benchmarks`.

El benchmark verifica una red equivalente 22.9 kV + línea radial y compara `Ik''`, `Sk''`, Rk y Xk. El CI exige `pass=true`. Esto cierra el subhito **P4C09A**, pero P4C09 global continúa `PENDING`.

## P4C05 — ip e Ith

Los motores 3F y 2F permiten solicitar `ip` e `Ith` mediante:

```text
calcular_ip_ith = true
topology = radial | meshed
tk_s > 0
kappa_method = C
```

Reglas fail-closed:

- `topology="auto"` no se acepta;
- `tk_s` debe ser finito y positivo;
- P4 v1 admite únicamente `kappa_method="C"` para este alcance;
- si falta cualquiera de estos datos, no se ejecuta `ip/Ith`;
- el payload conserva los parámetros efectivos en `input_projection.duty`.

`tk_s` no se inventa porque su valor depende del tiempo de despeje que más adelante deberá vincularse con P5/TCC.

## P4C06 — falla bifásica 2F

`mcp_electrico.iec60909_two_phase.ejecutar_2ph()` implementa la falla fase-fase sin tierra (`2ph`) para MAX y MIN.

La política declarada es:

```text
negative_sequence_policy = P4C06_Z2_EQUALS_Z1_SYMMETRIC_PASSIVE_SCOPE
Z2 = Z1
scope = red simétrica pasiva soportada actualmente
universal_assumption = false
```

La igualdad `Z2 = Z1` no se presenta como regla universal ni se aplica silenciosamente a generadores, motores o modelos asimétricos.

Resultados contractuales 2F actuales:

- `Ik''` (`ikss_ka`);
- Rk/Xk;
- `ip` e `Ith` cuando se solicitan con parámetros explícitos.

Aunque pandapower expone `skss_mw`, P4C06 no lo promociona a `Sk''` contractual para 2F.

El benchmark independiente 2F usa componentes simétricas y comprueba, dentro del alcance declarado:

```text
I1 = E / (Z1 + Z2)
Z2 = Z1
Ik''_2F = sqrt(3) * |I1|
Ik''_2F / Ik''_3F = sqrt(3) / 2
```

Esto permite marcar **P4C06 = DONE**, pero no cierra P4C09 global.

## P4C07 — falla monofásica a tierra 1F-T

`mcp_electrico.iec60909_single_phase_ground.ejecutar_1ph_ground()` implementa `fault="1ph"` para MAX/MIN con secuencia cero explícita y fail-closed.

### Secuencia positiva y negativa

La ruta 1F-T usa la misma secuencia positiva P2 que 3F/2F. Para el alcance simétrico pasivo actual se declara expresamente:

```text
negative_sequence_policy = P4C07_Z2_EQUALS_Z1_SYMMETRIC_PASSIVE_SCOPE
Z2 = Z1
explicit = true
universal_assumption = false
```

No se extiende esta relación a generadores, motores o modelos asimétricos.

### Z0 de fuente

P2 almacena R0/X0 absolutos por escenario. Pandapower 3.5.4 recibe relaciones en `ext_grid`, por lo que P4C07 proyecta:

```text
r0x0 = R0 / X0
x0x  = X0 / X1_backend
```

`X1_backend` usa el mismo Scc, X/R y factor de tensión `c` del escenario pandapower. Los tests verifican que la transformación conserva el R0/X0 absoluto P2. `X0=0` no se aproxima silenciosamente: bloquea la preparación.

### Z0 de líneas

Cada línea debe declarar:

- `r0_ohm_km`;
- `x0_ohm_km`;
- `c0_nf_km`.

`C0` es obligatorio aunque su valor físico declarado sea `0.0`; la ausencia de dato no se convierte en cero. Para MIN sigue siendo obligatorio `endtemp_degree`, y pandapower aplica la corrección de resistencia a R1 y R0.

### Z0 de transformadores y neutro

La ficha P2 homopolar se proyecta a pandapower mediante:

- `vk0_percent`;
- `vkr0_percent`;
- `mag0_percent`;
- `mag0_rx`;
- `si0_hv_partial`;
- `rn_ohm` / `xn_ohm` cuando existe neutro sólido o impedante;
- grupo vectorial efectivo coherente con el lado wye puesto a tierra.

Un transformador sin ficha Z0 proyectable o con devanado wye sin declaración explícita de neutro bloquea readiness.

### Resultados contractuales 1F-T

P4C07 promociona:

- `Ik''` (`ikss_ka`);
- Rk/Xk de secuencia positiva;
- Rk0/Xk0 de secuencia cero.

P4C07 **no** promociona actualmente:

- `Sk''` contractual para 1F-T;
- `ip`;
- `Ith`.

Pandapower 3.5.4 no ejecuta la ruta de cálculo `ip/Ith` en `_calc_sc_1ph`; MCP no rellena esas magnitudes mediante fórmulas paralelas solo para completar una tabla.

### Benchmark independiente 1F-T

`mcp_electrico.iec60909_benchmarks_1ph` resuelve una red 22.9 kV fuente + línea radial sin utilizar pandapower/OpenDSS como fuente del resultado esperado.

La referencia usa componentes simétricas:

```text
If = 3 * E / (Z1 + Z2 + Z0)
Z2 = Z1     [solo alcance simétrico pasivo P4C07]
Ik''_1F-T = sqrt(3) * c * Un / |2*Z1 + Z0|
```

El fixture declara C0=0 nF/km explícitamente para aislar la comparación de impedancias serie y usa 20 °C explícitos en MIN para que la corrección de resistencia sea unidad. Compara `Ik''`, Rk/Xk y Rk0/Xk0 para MAX/MIN.

Además existe un test de integración Dyn11 que compara neutro sólido con neutro impedante y exige que la impedancia de neutro reduzca la corriente 1F-T en la dirección física esperada.

Con esta cobertura **P4C07 = DONE**, pero P4 continúa `NOT_READY`.
